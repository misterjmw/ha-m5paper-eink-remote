# M5GFX Home Assistant E-Ink Dashboard for M5Paper

E-paper touch interface based on **M5GFX / ESP32** for controlling a **Home Assistant** setup.

Code and README generated by AI.

## ✨ Features

### Page 1 — Home

* 💡 **Lighting**

* Control of various lighting scenes: Sofa, Dinner, Movie, ..., All Off.
* 🏠 **Modes**

* Audio announcements
* Extended absence
* Automatic shutter closing
* 🎵 **Spotify**

* Track title and artist
* Previous / Play-Pause / Next
* 🌡️ **Climate Control**

* Heating / A/C / Off
* Temperature adjustment
* Current temperature/humidity

### Page 2 — Shutters & Wi-Fi

* 🪟 Shutter selection
* ⬆️ Open / ⏹ Stop / ⬇️ Close
* 📶 Wi-Fi voucher generation via Home Assistant
* Display of network, password, and last voucher

Page navigation is handled via two physical buttons.

## 🔌 Communication with Home Assistant

Commands are sent via:

```cpp
haCall(domain, service, entity, extra);
```

Example:

```cpp
haCall(
"light",
"turn_on",
"light.salon"
);
```

This corresponds to the call:

```text
POST /api/services/light/turn_on
```

Reading a state is done using:

```cpp
haState(entity, doc);
```

which uses:

```text
GET /api/states/<entity>
```

Authentication uses the Home Assistant token:

```http
Authorization: Bearer <TOKEN>
```

Each feature has its own touch handler:


The general workflow is:

```text

↓

↓
Identify button
↓

```

Buttons are briefly displayed in black while the command executes to provide visual feedback.

## 🪟 Blinds

Blinds are defined here:

The same set of commands is used for the selected blind:

```text

```

To add a blind, simply add an entry to the array and adjust `COVER_COUNT`.

## 📶 Wi-Fi Vouchers

The button:

```text
Activer hotspot
```

calls:

```text
input_button.press
```

on:

```cpp
ENTITY_WIFI_BUTTON
```

The program then waits for the voucher to be created and reads:

```cpp
ENTITY_WIFI_SENSOR
```

It expects to find a JSON `data` attribute containing, among other things:

```text
createdAt
code
```

This part is therefore **specific to the current setup** and will likely need to be adapted if the sensor structure changes.

## 🔋 Deep Sleep

To save power, the device enters deep sleep after:

```cpp
constexpr uint32_t DEEPSLEEP_TIMEOUT_MS = 60000;
```

i.e., **60 seconds of inactivity**.

The system can be disabled using:

```cpp
constexpr bool DEEPSLEEP_ENABLED = false;
```

Wake-up is triggered via the touch interface.

⚠️ The GPIOs used for the buttons, touch interface, and power supply depend on the M5 model:

```cpp
G37
G39
TOUCH_INT
MAIN_PWR
```

These must be verified before porting the program to another device. ---

## 🔧 Adapting the project to another setup

The main modifications required are:

```text
1. Create secrets.h
2. Configure Wi-Fi
3. Configure HA_HOST and HA_TOKEN
4. Replace Home Assistant entities
5. Adapt scenes / modes / blinds
6. Adapt Spotify
7. Adapt the voucher system if necessary
8. Check GPIOs if the hardware changes
```

To add a new feature, the recommended pattern is:

```text
Data
↓
drawXXX()
↓
touchXXX()
↓
haCall() / haState()
↓
Add to setupLayout() and loop()
```

## ⚠️ Key points to note

* Operation depends on Wi-Fi and Home Assistant availability.
* Home Assistant entities are currently hardcoded.
* Spotify is not continuously refreshed.
* The voucher sensor format is specific to the original setup.
* Deep sleep and GPIOs depend on the specific M5 hardware used.
* E-paper screens require special attention regarding ghosting; therefore, changing pages triggers a full screen refresh, whereas minor updates redraw only the specific card involved. ---

## 🚀 Overview

This project is an **ESP32/M5GFX-based e-paper home automation remote** using Home Assistant as the backend.

It centralizes the following controls on a small screen:

**lighting · modes · shutters · climate control · Spotify · Wi-Fi access**

The code structure is intentionally modular, making it easy to swap out Home Assistant entities and add new cards or controls.
