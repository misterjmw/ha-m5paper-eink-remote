# M5GFX Home Assistant e-ink Dashboard for M5Paper
Tactile e-paper interface based on **M5GFX / ESP32** allowing control of a **Home Assistant** installation.
Code and README generated by AI by Original Author: https://github.com/anteid
English Translation: MisterJMW

## ✨ Features

### Page 1 — Home

* 💡 **Lighting**

  * Control of different lighting scenes: Living room, Dinner, Movie, ..., all off.
* 🏠 **Modes**

  * Audio announcement
  * Extended absence
  * Automatic shutter closing
* 🎵 **Spotify**

  * Title and artist
  * Previous / play-pause / next
* 🌡️ **Air Conditioning**

  * Heating / AC / Off
  * Temperature setting
  * Current temperature/humidity

### Page 2 — Shutters & Wi-Fi

* 🪟 Shutter selection
* ⬆️ Raise / ⏹ Stop / ⬇️ Lower
* 📶 Wi-Fi voucher generation via Home Assistant
* Display of network, password, and last voucher

Navigation between pages is done with two physical buttons.

## 🔌 Communication with Home Assistant

Commands go through:

```cpp
haCall(domain, service, entity, extra);
```

Example:

```cpp
haCall(
  "light",
  "turn_on",
  "light.salon"
);
```

Which corresponds to the call:

```text
POST /api/services/light/turn_on
```

Reading a state is done with:

```cpp
haState(entity, doc);
```

which uses:

```text
GET /api/states/<entity>
```

Authentication uses the Home Assistant token:

```http
Authorization: Bearer <TOKEN>
```

## 🪟 Shutters

Shutters are defined here:

```cpp
CoverCard covers[] = {
  {"CUISINE", "cover.xxx"},
  {"SALON",   "cover.xxx"}
};
```

The same set of commands is used for the selected shutter:

```text
       ↑
     STOP
       ↓
```

The Home Assistant services used are:

```text
cover.open_cover
cover.stop_cover
cover.close_cover
```

To add a shutter, simply add an entry to the array and adapt `COVER_COUNT`.

## 📶 Wi-Fi Vouchers

The button:

```text
Activate hotspot
```

calls:

```text
input_button.press
```

on:

```cpp
ENTITY_WIFI_BUTTON
```

The program then waits for the voucher creation and reads:

```cpp
ENTITY_WIFI_SENSOR
```

It expects to find a JSON `data` attribute containing among others:

```text
createdAt
code
```

This part is therefore **specific to the current installation** and will likely need adaptation if the sensor structure changes.

## 🔋 Deep Sleep

To save energy, the device enters deep sleep after:

```cpp
constexpr uint32_t DEEPSLEEP_TIMEOUT_MS = 60000;
```

i.e. **60 seconds of inactivity**.

The system can be disabled with:

```cpp
constexpr bool DEEPSLEEP_ENABLED = false;
```

Wake-up is done via the touch screen.

⚠️ GPIOs used for buttons, touch, and power depend on the M5 model:

```cpp
G37
G39
TOUCH_INT
MAIN_PWR
```

They must be verified before porting the program to another device.

## 🔧 Adapting the Project to a Different Installation

The main modifications are:

```text
1. Create secrets.h
2. Configure Wi-Fi
3. Configure HA_HOST and HA_TOKEN
4. Replace Home Assistant entities
5. Adapt scenes / modes / shutters
6. Adapt Spotify
7. Adapt the voucher system if necessary
8. Verify GPIOs if hardware changes
```

To add a new feature, the recommended model is:

```text
Data
  ↓
drawXXX()
  ↓
touchXXX()
  ↓
haCall() / haState()
  ↓
Add in setupLayout() and loop()
```

## ⚠️ Points to Note

* Operation depends on the availability of Wi-Fi and Home Assistant.
* Home Assistant entities are currently hardcoded.
* Spotify is not refreshed continuously.
* The voucher sensor format is specific to the original installation.
* Deep sleep and GPIOs are dependent on the M5 hardware used.
* E-paper screens require particular attention to ghosting; page change therefore performs a full clear while small modifications only redraw the concerned card.

## 🚀 In Summary

This project is an **e-paper smart home remote control based on ESP32/M5GFX**, with Home Assistant as the backend.

It allows centralizing on a small screen:

**lighting · modes · shutters · air conditioning · Spotify · Wi-Fi access**

The code structure is intentionally modular to be able to replace Home Assistant entities and easily add new cards or commands.
